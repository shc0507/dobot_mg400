# Host deployment

[Project home](../README.en.md) · [Installation](#installation-and-updates) · [Configuration](#configuration-file) · [Routine commands](#routine-commands) · [Connection lock](#panel-connection-lock) · [Migration](#migration-to-a-new-host)

This page explains how to install, update, and run the project's services on a Linux host.
Deployment does not depend on a specific platform. For Olares networking, code access, and USB troubleshooting, see [Olares configuration and maintenance](olares.en.md).

## Installed components

| Path | Contents | Owner and permissions |
| --- | --- | --- |
| `/opt/mg400` | Git working copy and Python environment `.venv` | `root:1000`, `0750` |
| `/etc/mg400/mg400.env` | Configuration and access tokens for this host | `root:root`, `0600` |
| `/etc/mg400/go2rtc.yaml` | Camera capture configuration generated by the installer | `root:1000`, `0640` |
| `/var/lib/mg400` | Parent directory for runtime data | `root:1000`, `0750` |
| `/var/lib/mg400/locks` | Robot connection locks | `1000:1000`, `0700` |
| `/var/lib/mg400/work` | Gripper feedback, gripper command files, and mode-switch backups | `1000:1000`, `0750` |
| `/var/lib/mg400/camera` | Camera preview token `preview.key` | `1000:1000`, `0700` |
| `/usr/local/lib/mg400/go2rtc` | go2rtc 1.9.14 camera capture program | `root:root`, `0755` |
| `/usr/local/bin/mg400ctl` | Routine command tool, linked to `/opt/mg400/deploy/mg400ctl` | None |

All services run as the user and group with numeric ID `1000`.
Service definitions are in `config/systemd/` and are installed in `/etc/systemd/system/`:

| Service | `mg400ctl` name | Purpose | Supplementary groups |
| --- | --- | --- | --- |
| `mg400-web-panel.service` | `web` | [Web panel](control-panel.en.md), port `8766` | None |
| `mg400-stage-panel.service` | `stage` | [Stage panel](stage-panel.en.md), port `8767` | `dialout` |
| `mg400-camera-preview.service` | `camera` | Camera preview page, port `1985` | None |
| `mg400-camera-capture.service` | `camera` | go2rtc capture, listening only on `127.0.0.1:1984` | `video` |
| `mg400-gripper-collector.service` | `collector` | Gripper USB collection | `dialout` |
| `mg400-gripper-collector.path` | None | Start gripper collection when the panel requests it | None |

Start services manually. They do not start automatically at boot.
After a host restart, only the gripper collection request listener resumes automatically.

## Prerequisites

- The host runs Linux and systemd.
- `/usr/bin/python3` is Python 3.12 or later.
- Git, `setpriv`, and [uv](https://docs.astral.sh/uv/getting-started/installation/) are installed on the host.
- The host can access PyPI. `uv sync` downloads dependencies from PyPI.
- A host network interface connects directly to the robot and has address `192.168.1.10/24`.
- This interface can connect to the robot's TCP ports `29999`, `30003`, and `30004`.
- For cameras, download the Linux program for version 1.9.14 from the [go2rtc releases page](https://github.com/AlexxIT/go2rtc/releases/tag/v1.9.14).

## Installation and updates

Run the commands in this section as root.
Before an update, stop the services with `mg400ctl stop all`.

1. Get the code. For the first installation, run:

   ```sh
   git clone https://github.com/shc0507/dobot_mg400.git /opt/mg400
   ```

   For an update, switch to the target commit:

   ```sh
   git -C /opt/mg400 fetch origin
   git -C /opt/mg400 switch --detach origin/main
   ```

   If the host cannot access GitHub, get the code through a Git bundle. See [When GitHub is unavailable on Olares](olares.en.md#when-github-is-unavailable).

2. Run the installer:

   ```sh
   /usr/bin/python3 /opt/mg400/deploy/install.py
   ```

   For cameras, add `--go2rtc <go2rtc 程序路径>` with the go2rtc program path on the first installation.
   With `--dry-run`, the installer only lists its steps and does not change the host.

3. After the first installation, edit the configuration as described in [Configuration file](#configuration-file).
4. Start or restart services. See [Routine commands](#routine-commands).

The installer works in this order:

1. Check the Python version, uv, the configuration file, and any independently running gripper collection processes. If a check fails, leave the host unchanged.
2. Create the configuration file or add missing entries. Fill empty `*_TOKEN` entries with newly generated access tokens. Keep existing values.
3. Create the directories under `/var/lib/mg400` and the camera preview token.
   Refuse symbolic links there and do not overwrite existing tokens.
4. Run `uv sync` to install the stage and tool dependencies in `/opt/mg400/.venv`.
5. If cameras are configured, install go2rtc and generate `go2rtc.yaml`. Otherwise, remove the old `go2rtc.yaml`.
6. Install service definitions, reload systemd, and enable the gripper collection request listener.
7. Create the `mg400ctl` link.

The installer does not start, stop, or restart services.
You must stop services before updating the code. Running services can read a mixture of old and new files.
After the update, start services, then reload any open panel pages.
Do not edit files in `/opt/mg400`. Modified files can cause `git switch` to abort the update.

## Configuration file

`/etc/mg400/mg400.env` stores all configuration for this host.
Services read this file at startup. After a change, restart the affected service.
Empty entries use their defaults, except for `MG400_CONTROLLER_LOCK_DIR`.
Values must not contain quotes or backslashes. The installer and `mg400ctl` reject lines that systemd could interpret differently.
Each time it runs, the installer restores this file's owner to `root:root` and permissions to `0600`.

| Setting | Default | Purpose |
| --- | --- | --- |
| `MG400_ROBOT_HOST` | Address in `config/robot.toml` | Robot address |
| `MG400_CONTROLLER_LOCK_DIR` | Required, for example `/var/lib/mg400/locks` | [Panel connection lock](#panel-connection-lock) directory, which must be an absolute path |
| `MG400_PANEL_BIND` | `127.0.0.1` | Web panel bind address |
| `MG400_PANEL_PORT` | `8766` | Web panel port |
| `MG400_PANEL_TOKEN` | Generated by the installer | Web panel access token |
| `MG400_CAMERA_BIND` | `127.0.0.1` | Camera preview bind address |
| `MG400_CAMERA_DEVICES` | Empty | 3 camera devices separated by commas. Empty means no camera configuration |
| `MG400_STAGE_BIND` | `127.0.0.1` | Stage panel bind address |
| `MG400_STAGE_PORT` | `8767` | Stage panel port |
| `MG400_STAGE_TOKEN` | Generated by the installer | Stage panel access token |
| `MG400_STAGE_SERIAL` | Empty | Arduino serial port path. See [Stage configuration](stage-panel.en.md#configuration) |

When a panel listens on a non-loopback address, its access token must have at least 24 characters.
Use camera device paths under `/dev/v4l/by-path/`. These paths distinguish 3 cameras of the same model by their USB ports.
The camera preview always shows 3 streams.
After changing `MG400_CAMERA_DEVICES`, run the installer again to generate a new `go2rtc.yaml`, then restart the cameras.

## Routine commands

Run `mg400ctl` as root, for example `sudo mg400ctl status`:

| Command | Effect |
| --- | --- |
| `mg400ctl status` | Show the status of all services |
| `mg400ctl start web stage camera` | Start services. Names are `web`, `stage`, `camera`, `collector`, or `all` |
| `mg400ctl stop all` | Stop services |
| `mg400ctl restart web` | Restart services |
| `mg400ctl logs web -n 100` | Show service logs. Add `-f` for continuous output |
| `mg400ctl terminal` | Open the [interactive terminal](terminal-control.en.md) |
| `mg400ctl mode` | Read the controller mode. See [Switching TCP/IP mode](hardware.en.md#switch-to-tcpip-mode-from-the-server) |
| `mg400ctl camera-url` | Show the camera preview link with its access token |
| `mg400ctl camera-check` | Check camera devices, services, and capture streams in order. See [Camera failures](olares.en.md#camera-failures) |
| `mg400ctl token web` | Show the web panel access token. `token stage` shows the stage panel token |

`terminal` and `mode` use `runuser --pty` to run as UID 1000 in a separate pseudo-terminal.
They read the configuration file and share the panel's connection lock, but do not receive access tokens.
When the web panel stops or restarts, it can take up to approximately 60 seconds to confirm that the robot stopped.
You do not need to start gripper collection manually. The web panel or interactive terminal requests collection when it connects to the robot.

## Panel connection lock

The web panel, interactive terminal, and mode-switch tool acquire a file lock before connecting to the robot.
The web panel's read-only mode also uses this lock.
If another program holds the lock, a new connection returns `Robot controlled by another panel`.
After a normal disconnect, the panel waits for the feedback thread and command tasks to end before releasing the lock.
If it cannot confirm the stopped state, the panel stops routine coordinate queries and keeps feedback and the lock.
Reloading the panel page cannot clear an unconfirmed stopped state.

All programs must use the same robot address and `MG400_CONTROLLER_LOCK_DIR`.
The lock directory must use an absolute path and support operating-system file locks.
All programs run as UID 1000. Lock file permissions are `0600`.
When running as root, the program refuses lock directories not owned by root.
If an existing lock file has a different owner, the program changes its owner in place and preserves the original file.

Do not remove lock files to release ownership. When a process exits, the operating system releases the locks that process holds.
A process exit does not confirm that the robot stopped.
This lock does not restrict DobotStudio or other hosts. Close other control programs before use.

## Migration to a new host

1. Stop services on the old host and disable the gripper collection request listener:

   ```sh
   mg400ctl stop all
   systemctl disable --now mg400-gripper-collector.path
   ```

2. Prepare the new host according to [Prerequisites](#prerequisites), then install according to [Installation and updates](#installation-and-updates).
3. Copy `/etc/mg400/mg400.env` from the old host to the new host. Adjust bind addresses and camera devices for the new host.
   Copy with `install -o root -g root -m 0600`. If you preserve access tokens, users do not need to enter them again.
4. To preserve camera preview links, copy `/var/lib/mg400/camera/preview.key` to the same path on the new host with owner `1000:1000`.
5. If `/var/lib/mg400/work/gripper_feedback.json.command-lock.json` exists on the old host, a gripper command outcome is unconfirmed.
   First check the gripper state. Then copy the file to the same path on the new host with owner `1000:1000` and permissions `0600`.
   When the new host's collection service reads this file, it stays locked, as on the old host.
6. After changing camera devices, run the installer again.
7. Connect the robot network interface and USB devices, then start services.
