# 0008：通过审批控制 LLM 智能体

## 状态

已被取代：2026-11-09。网关和提议流程已删除。智能体改用 `labctl` 命令行工具，见 ADR 0010。

已接受：2026-10-30。2026-11-02 增加审批策略（H-23）。

## 背景

智能体必须能读取实验室状态和运行历史。设备动作必须由人员明确批准。

## 决定

在阶段 5 引入 LLM 网关。使用 Python MCP SDK、Streamable HTTP、回环端口 8773 和 Bearer 令牌。

| 工具 | 允许的动作 |
| --- | --- |
| `list_services`, `get_state(service)` | 读取服务发现信息和状态 |
| `list_recipes`, `describe_recipe` | 读取可用配方及定义 |
| `list_runs`, `get_run`, `get_chip(id)` | 读取运行历史和芯片记录 |
| `propose_run(recipe, params, reason)` | 策略检查通过后创建审批请求 |
| `get_approval(id)` | 读取审批决定 |

- 初始仅提供读取工具。读取不要求动作审批。每次网关调用均写入运行记录，包含调用方、工具、参数和时间。
- 提案遵守下方的审批策略。
- 每项审批记录配方、参数、申请人、原因、创建时间、决定和决定人。存储提案前检查策略限制。
- 仪表盘显示完整配方和参数，并提供批准与拒绝按钮。批准的运行由编排器按手动运行的方式启动。
- 网关工具不得直接发送设备命令。拒绝、过期和超限均不授权执行。审批不能取消服务租约、停止控制或安全检查。

### 审批策略（H-23，2026-11-02）

所有者把本策略委托给迁移协调员制定。所有者可以在本 ADR 中修改。

| 规则 | 值 |
| --- | --- |
| 审批人 | 仪表盘前的人员。网关不能审批，智能体不能审批自己的提案。每项审批记录审批人的客户端标识。 |
| 在场要求 | H-24 批准无人值守运行之前，只有在实验室有人能操作停止按钮时才批准运行。 |
| 允许的配方 | 仓库配方目录中的配方。 |
| 拒绝的步骤 | 位移台原始移动、细分设置和固件命令。 |
| 炉子 | 允许设定值、程序和气体步骤，但不得超过主机上限（`MG400_FURNACE_MAX_C`、`MG400_FURNACE_MAX_RAMP`），且只能使用主机气体映射中的气体。 |
| 任意机械臂坐标 | 只有在工作空间边界内（`MG400_ORCH_*_MIN_MM`、`MG400_ORCH_*_MAX_MM`）、使用服务速度上限、且运行期间有人在场时，才允许 `robot.move`；H-24 之后也是如此。这是为以后的示教学习工作保留的接口。 |
| 坩埚限值 | `load_max_c`、`unload_max_c`、`awake_s` 和 `max_age_s` 来自主机设置，提案不能设置。 |
| 速度 | 速度参数不得超过配方默认值。服务上限仍然有效。 |
| 过期 | 30 分钟内无人决定即过期。 |
| 待定提案 | 同时最多 3 个。 |

## 影响

智能体可在无动作权限时查看实验室状态。提案在编排器启动运行前建立可审计的决定环节。
