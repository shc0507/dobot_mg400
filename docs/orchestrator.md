# 配方编排器

编排器跨仪器服务执行配方。配方是带版本的 TOML 文件，包含参数和有序操作步骤。操作单元是注册表中的具名操作。每次运行记录步骤、芯片身份、样本、产物和安全结果。

## 命令

在仓库内使用项目环境：

```sh
uv run labctl rehearse recipes/example-rehearsal.toml --runs-dir ./rehearsal-runs
uv run labctl runs --runs-dir ./rehearsal-runs
uv run labctl runs RUN_ID --runs-dir ./rehearsal-runs
```

`labctl run RECIPE` 使用配置的仪器服务。真机运行前，必须完成操作员检查。操作员必须守在急停旁。Shell 智能体使用[智能体命令行](agent-cli.md)。

`--runs-dir PATH` 指定记录目录。`--param NAME=JSON` 覆盖配方声明的参数。字符串值必须使用 JSON 字符串引号：

```sh
uv run labctl rehearse recipes/example-rehearsal.toml --runs-dir ./rehearsal-runs --param 'chip_id="demo-chip-2"' --time-scale 0.1
```

`--time-scale` 必须为正数，只用于演练。默认值为 `0.1`。它缩短模拟等待，步骤超时仍按实际时间计算。

## HTTP 服务

服务 `orch` 通过 Flask 和 waitress 运行 `python -m orchestrator serve`。
按[服务清单](deploy.md#服务清单)安装。它不使用设备组，也不自动启动配方。
上文的 CLI 命令不需要该服务即可运行。

服务监听 `127.0.0.1:8772`。安装的单元设置基础路径 `/lab/`，由代理提供。控制台控制套接字监听 `127.0.0.1:8774`，代理把 `/lab/api/console/socket` 转发到该端口。端口被占用时，服务记录警告并照常启动，页面改用 HTTP。
它从 `/opt/mg400/recipes` 读取配方目录。
`--bind`、`--port`、`--base-path`、`--recipes-dir` 和 `--runs-dir` 可覆盖这些默认值。
未指定选项时，服务使用 `127.0.0.1`、`8772`、`/`、`/opt/mg400/recipes` 和 `/var/lib/mg400/runs`。安装的单元传入 `--base-path /lab/`。

POST 请求必须带 `Content-Type: application/json` 和 `X-MG400-Client`，后者使用固定的调用者身份。
通过 `/api/heartbeat` 获取并续期前端控制租约。下表所有自定义修改路由都要求持有该租约。
共享的 `/api/stop` 仍对任何客户端开放，用于暂停当前运行或取消恢复。
前端租约释放或过期也会请求暂停或取消恢复。

下列路径都相对于配置的基础路径：

| 方法与路径 | 请求或结果 |
| --- | --- |
| `GET /api/recipes` | 列出配方标识、名称和参数声明 |
| `POST /api/runs` | 提供必填的 `recipe` 标识和可选的 `params` 对象后启动。带 `borrow: true` 时，运行使用该客户端控制台页面持有的设备，租约仍由控制台持有 |
| `GET /api/runs` | 列出运行记录 |
| `GET /api/runs/<id>` | 读取运行及其已记录结果 |
| `POST /api/runs/<id>/resume` | 提供 `manually_completed: true` 和非空 `note`。此运行保留区域占用时，还必须提供 `physically_clear: true` |
| `POST /api/runs/<id>/abort` | 用空对象终止当前运行 |
| `POST /api/runs/<id>/recovery` | 用空对象开始恢复已结束运行保留的占用 |
| `POST /api/runs/<id>/recovery/confirm` | 确认 `physically_clear: true` 并填写非空 `note` |
| `POST /api/runs/<id>/recovery/abort` | 用空对象取消恢复 |

配方标识是配方目录中不带 `.toml` 的文件名，格式为 `[A-Za-z0-9][A-Za-z0-9_-]{0,95}`。配方文件必须是普通文件，不超过 256 KiB。目录最多含 256 个配方，路径中不得有符号链接。`note` 最多 2000 个字符。

修改请求被接受后返回 `202` 和 `command_id`。轮询 `/api/state` 和 `/api/runs/<id>`，读取异步结果。
请求被接受不能证明已完成。同一时间只能有 1 个运行或恢复会话。
获取设备租约前，先校验完整配方及其所需的区域条件服务。

契约路由 `POST /api/command` 接受 `hold` 和 `abort`，参数为空对象。`hold` 暂停当前运行并取消恢复，`abort` 终止当前运行。`/api/stop` 接受 0 至 15 的 `wait_s`，返回 `confirmed`、`unconfirmed` 或 `pending`。控制台和总览路由见[实验室控制台](dashboard.md)。

当前运行按下文的人工完成和等待旧操作结束规则恢复。它进入下一步，不重放失败步骤。
已结束运行的恢复另行处理。首个请求创建新的客户端身份，并在人工检查期间保持所需租约。
此请求不会清除占用。确认前，检查现场区域已清空，并完成设备恢复。
确认时，重新检查停止或已验证的静止状态、控制权和健康状态，记录清空声明后才删除已核对的占用。
取消、租约丢失或关闭服务时，停止并等待恢复操作结束，再释放租约，保留占用。
恢复不会重新启动已记录的配方。

收到 `SIGTERM` 时，服务请求暂停，并等待已接受的工作和停止操作结束。
关闭前，服务记录运行状态并释放租约。关闭后仍保留区域占用。
systemd 单元会等待清理完成。重启不会恢复已保存的运行，也不会清除其区域。

要启动隔离的本地服务，运行：

```sh
uv run python -m orchestrator serve --demo --recipes-dir ./recipes
```

演示启动时，在创建线程前从进程环境中移除下游端点和凭据、设备路径及代理配置。
它独占临时运行记录、占用文件、设备模拟器和控制器锁。
环境中的记录路径和占用路径会被忽略。`--demo` 不接受 `--runs-dir`。
配方目录保持只读。明确提供的工位、工具、工作空间和区域配置仍可作为只读输入。
演示初始化不能证明现场区域已清空。服务关闭时删除临时数据。

## 配方

CLI 先校验完整配方，再创建记录、启动演示服务或获取控制租约。未知操作单元、缺少参数、类型错误、超时无效或未知字段都会拒绝。

```toml
name = "Record a sample"
version = 1

[params.chip_id]
type = "string"
default = "demo-chip"

[[steps]]
skill = "sample.record"
params = { chip_id = "${chip_id}", note = "Example record" }
timeout_s = 1
on_fail = "hold"
```

配方顶层必须恰好包含 `name`、`version`、`params` 和 `steps`。`version` 必须为 `1`。没有参数时，写 `params = {}`。参数名格式为 `[A-Za-z_][A-Za-z0-9_]*`。参数类型为 `string`、`integer`、`number` 或 `boolean`。没有默认值的参数必须提供覆盖值。`${chip_id}` 替换完整参数值，并保留类型。每步必须包含 `skill`、`params` 和正有限数 `timeout_s`，可选 `on_fail` 和 `zone`。`on_fail` 默认为 `hold`：运行暂停，等待人工处理。`abort` 在停止后终止运行。

| 操作单元 | 参数 | 服务 |
| --- | --- | --- |
| `wait` | `seconds` | 无 |
| `fail` | `message` | 无 |
| `robot.enable` | 无 | 机器人 |
| `robot.move` | `x_mm`、`y_mm`、`z_mm`、`r_deg` | 机器人 |
| `robot.stop` | 无 | 机器人 |
| `robot.pick` | `station`，可选 `speed` | 机器人 |
| `robot.place` | `station`，可选 `speed` | 机器人 |
| `robot.transfer` | `from`、`to`，可选 `speed` | 机器人 |
| `vision.check_calibration` | `camera` | 机器人、视觉 |
| `vision.calibrate` | 见[视觉](vision.md) | 机器人、视觉 |
| `vision.find_chip` | `slot` | 机器人、视觉 |
| `vision.slot_state` | `slot` | 机器人、视觉 |
| `vision.pick_chip` | `slot`，可选 `speed` | 机器人、视觉 |
| `vision.tray_transfer` | `from_slot`、`to_slot`，可选 `speed` | 机器人、视觉 |
| `crucible.load` | `from_slot`，可选限制见下文和 `speed` | 机器人、电动台、高温炉 |
| `crucible.unload` | `to_slot`，可选限制见下文和 `speed` | 机器人、电动台、高温炉、热成像 |
| `microscope.record` | `chip_id`、`seconds`，可选 `run_name`、`mode` | 显微镜 |
| `sample.record` | `chip_id`、`note` | 无 |

`recipes/example-rehearsal.toml` 示例使能模拟机器人，移动后记录样本，再停止机器人。它不含供气或加热命令。自定义操作单元接收可撤销的上下文，其中包含服务客户端、运行记录和区域管理器。进入命名区域必须有明确配置，并检查配置的进入条件。

## 服务配置

每次运行使用唯一客户端身份。运行器先检查所需服务的契约，再获取首个控制租约。续期只延长现有租约，不会重新获取。租约丢失后，运行保持暂停，不能通过自动获取控制权恢复。

以下值固定在代码中：

| 项目 | 值 |
| --- | --- |
| 记录目录 | `/var/lib/mg400/runs`，`--runs-dir` 可覆盖 |
| 客户端超时 | `2` s |
| `robot` | `http://127.0.0.1:8766/` |
| `stage` | `http://127.0.0.1:8767/contract/` |
| `thermal` | `http://127.0.0.1:8768/` |
| `furnace` | `http://127.0.0.1:8769/` |
| `microscope` | `http://127.0.0.1:8770/` |
| `vision` | `http://127.0.0.1:8771/` |

区域文件为默认值。演练和测试设置非空值以使用自有文件：

| 项目 | 设置 | 默认值 |
| --- | --- | --- |
| 区域配置 | `MG400_ORCH_ZONES_FILE` | `/var/lib/mg400/zones/config.toml` |
| 持久占用记录 | `MG400_ORCH_ZONE_STATE_FILE` | `/var/lib/mg400/zones/occupancy.json` |

服务不检查令牌。服务适配器直接连接，不使用代理配置。见[服务契约](adr/0001-instrument-service-contract.md)。

## 区域与进入条件

区域是带所属设备和进入条件的共享物理空间。
配置指定允许进入的所属设备，占用记录标识当前持有者。
其他持有者等待区域释放，超时后失败。
区域等待不能超过步骤剩余时限。自定义区域上下文可以指定更短的超时。
配置缺失或区域未知时，拒绝进入，不会跳过区域检查。

安装器创建 `/var/lib/mg400/zones`，属主为 `1000:1000`，权限为 `0750`。
默认配置文件不存在时，配置中没有区域：不含 `zone` 的配方照常运行，进入任何区域都被拒绝。
将配置保存到 `/var/lib/mg400/zones/config.toml`，属主为 `1000:1000`，权限为 `0640`。
使用本地路径时，父目录必须属于调用者，权限为 `0700` 或 `0750`。
配置和占用记录只接受具有规定属主的常规文件，权限为 `0600` 或 `0640`。
存储拒绝不安全的父目录和任何路径分量中的符号链接，在已有的所属目录中原子写入占用记录。
控制同一设备的所有硬件运行必须使用相同的配置和占用路径。

存储争用最多等待 2 秒，且不能超过步骤剩余时限。同一进程内的线程排队等待，停止或撤销会取消等待。设备停止命令先于区域存储写入发送。
发布前发生写入、文件同步或替换失败时，保留旧占用记录。
替换后目录同步失败会报错，但新状态可能已经可见。
只有验证离开或核对现场清空恢复后，才会出现已释放的占用。报错后，不要假定操作已回滚。

区域配置如下：

```toml
[zones.tray]
owner = "robot"
conditions = []

[zones.crucible-load]
owner = "robot"
conditions = ["stage_at_load"]

[zones.furnace-tube]
owner = "stage"
conditions = ["robot_clear"]
```

自定义区域名称也必须明确指定所属设备和条件。所属设备使用上方配置表中的服务名称：`robot`、`stage`、`thermal`、`furnace`、`microscope` 或 `vision`。
名称含 1 至 64 个字母、数字、下划线或连字符，以字母或数字开头。
未知字段、未知条件和重复条件均被拒绝。
保留区域 `crucible-load` 必须属于机器人，并要求 `stage_at_load`。
保留区域 `furnace-tube` 必须属于位移台，并要求 `robot_clear`。机器人不能持有它，也不得进入显微镜下方。
`crucible-load` 和 `furnace-tube` 不能同时被占用。`crucible-load` 被占用时，位移台不接受动作。其他运行在某设备上保留占用时，本次运行不能操作该设备。
这些所属设备检查不能证明任意 `robot.move` 命令都会避开显微镜。
仍须由操作员验证路线和工作空间限位。

| 条件 | 所需状态 |
| --- | --- |
| `stage_at_load` | 位移台状态必须新鲜、已连接、健康，且由本次运行控制。全部 3 轴必须已回零、可自动移动且空闲。Insert 必须保持唤醒，并在 `at_positions` 中报告 `load`。 |
| `robot_clear` | `crucible-load` 无持久占用记录。本次运行还必须持有机器人的控制租约。 |

获取租约前，运行器先解析条件所需的服务。
条件检查不依赖仍由手动控制的服务。仅为条件获取的客户端不向操作单元开放写操作。
检查使用报告的命名位置，不根据坐标猜测装卸位置。
保持唤醒时间不自动续期。条件失效时，运行保持暂停并请求停止。

配方步骤可以声明 `zone = "tray"`。运行器在步骤前后检查该区域。
普通步骤完成后保留持久占用记录。步骤成功不能证明设备已离开区域。
工位操作单元仅在明确的测量离开点释放占用。
异常、终止和进程退出均保留占用。空闲反馈和租约过期都不会清除占用。

运行快照通过 `zones` 报告占用，通过 `zone_error` 报告失败。
清除保留的占用前，先到现场确认区域已清空。
当前暂停运行的恢复要求声明人工完成，并填写非空备注。
只有当前运行持有保留占用时，才额外要求单独声明 `physically-clear`。
恢复会记录该声明。其他运行的占用不会触发此声明，也不能通过当前运行的恢复清除。

每次恢复前，旧工作都必须结束，并重新确认停止或验证机器人静止，再确认控制权匹配和服务健康状态。
当前运行未持有占用时，暂时的条件检查失败可在通过这些检查后按常规人工完成流程恢复。
此操作只清除暂时错误，不清除其他运行的占用，也不重放失败步骤。
恢复不会重新获取丢失的租约。

旧进程留下的占用也必须通过有审计记录的恢复清除，并使用已持有控制权的客户端。
已安装的服务在 `POST /api/runs/<id>/recovery` 和 `/recovery/confirm` 提供此恢复。它清除该运行在服务记录库中保留的占用，见 [HTTP 服务](#http-服务)。持有者不在该记录库中时，使用下文的 Python API。
不得通过删除或替换占用文件清除占用。

### 恢复已退出进程的占用

公开 Python API 为 `orchestrator.zones.Zones.recover`。
操作员必须先检查设备，并确认现场区域已清空。旧进程必须已退出。
使用相同的区域配置和占用路径。在恢复应用中准备以下参数：

| 参数 | 要求 |
| --- | --- |
| `recipe`、`registry` | 已验证的配方及其操作单元注册表，传给 `prepare_zones`。 |
| `zone_settings` | 包含 `MG400_ORCH_ZONES_FILE` 和 `MG400_ORCH_ZONE_STATE_FILE` 的映射。 |
| `recovery_services` | 按服务名称映射公开适配器。它们必须已持有保留占用记录中全部服务的控制权，恢复期间保持租约有效。 |
| `recovery_id` | 此恢复管理器的唯一身份。 |
| `old_holder` | `manager.snapshot()` 占用记录中保留的持有者标识。 |
| `record_event` | 接收事件类型和数据的回调。必须持久保存审计事件。持久保存失败时返回 `False` 或抛出异常。 |
| `operator_note` | 非空说明，记录现场检查和人工处理。 |

```python
from orchestrator.zones import Zones, prepare_zones

plan = prepare_zones(recipe, registry, settings=zone_settings)
manager = Zones(plan, recovery_services, holder=recovery_id, audit=record_event)
manager.recover(
    old_holder,
    recovery_services,
    physically_clear=True,
    note=operator_note,
)
```

此调用读取发现接口，验证现有控制权，再清除此次核对的占用记录。
确认旧工作已结束或旧进程已退出后，必须重新确认停止或验证机器人静止，并确认服务健康且空闲。
机器人静止验证使用与当前运行恢复相同的明确人工 `disable` 证明。没有完整证明时，请求 Stop。
机器人必须提供实例 ID，通用契约服务可以省略。
提供实例 ID 时，该值必须为非空字符串，且在恢复期间保持不变。
占用记录并发变化时，拒绝清除。
旧进程仍存活、所需服务缺失或停止未确认时，拒绝恢复。
此调用不会获取租约。持久保存失败时，不会返回恢复成功。
恢复仍存活的暂停运行时，改用运行器的恢复提示。

## 暂停与终止

失败或超时后，运行器撤销失败步骤，并请求所有已获取控制权的服务停止。使用 `on_fail = "hold"` 时，它保留租约并等待人工处理。它不会重试失败步骤。

在提示处输入 `abort`，终止运行。人工完成操作后，输入 `manually-completed` 并填写非空处理说明。旧工作线程、辅助调用和正在执行的服务操作都必须结束。随后，运行器要求新的停止确认，或在明确的人工 `disable` 后验证机器人静止。机器人静止证明要求最近命令确认下使能成功、当前反馈显示已下使能且空闲，以及键盘无活动。没有完整证明时，以及普通停止、暂停、终止和清理期间，运行器都发送 Stop。

所有服务必须正常、保持原控制权，并报告 `busy = false` 和 `locked = false`。通用服务还必须满足 `fault = null`，提供的实例 ID 也必须保持一致。机器人必须有新鲜同步反馈、`robot_error = false`、`stop_unconfirmed = false`，以及有效且不变的实例 ID。运行器不会自动下使能机器人。租约丢失或审计记录写入失败时，不得恢复。运行器记录人工完成结果并执行下一步，处理说明遭拒时则保持暂停。

EOF、Ctrl-C、SIGTERM 和 SIGHUP 都会请求终止。CLI 等待活动操作和停止操作结束，再关闭记录库或演示服务。重复中断不会绕过等待。

数据库写入失败时，CLI 仍输出内存中的安全报告。检查 `stops`、`unconfirmed_services`、`persistence_error` 和 `release_errors`。`aborted` 状态不能证明所有设备已停止。服务无法确认停止时，保持工作区域无人，并按设备恢复流程处理。

## 运行记录

数据库位于记录目录中的 `runs.db`。每次运行的文件放在独立的 `RUN_ID` 目录。样本记录必须有 `chip_id`。记录库只接受规定的属主、安全文件类型和私有权限。记录路径中不得有符号链接。

`labctl runs` 只读取历史，不获取服务控制权。指定运行 ID 后，可查看步骤、样本、产物和事件。该命令不会恢复或重启已有运行。旧进程留下暂停记录时，操作员必须先恢复设备，再开始新运行。

## 工位示教与工具偏移

工位保存测得的指尖（吸盘工具端点）位姿、接近间隙，以及可选的途经工位路线。控制器必须保持 `User=0,Tool=0`。工具偏移只在软件中换算。

操作员必须把 H-08 测得的偏移写入 `/var/lib/mg400/robot/tool.toml`。文件只含 `offset_mm = [dx, dy, dz]`。用测得的有限数替换这些名称，单位为毫米。偏移没有默认值。测量值缺失或无效时，不能示教。

换算先按法兰角度 R 旋转 `(dx, dy)`，再加到法兰 XY 上。指尖 Z 等于法兰 Z 减去 dz。反向换算减去旋转后的 XY 偏移，并加上 dz。两种换算都保留 R，包括正负号和完整转数。

工具文件为 `MG400_ORCH_TOOL_FILE`，默认为 `/var/lib/mg400/robot/tool.toml`。工位文件为 `MG400_ORCH_STATIONS_FILE`，默认为 `/var/lib/mg400/robot/stations.toml`。

指尖工作空间由 8 个设置定义：`MG400_ORCH_X_MIN_MM`、`MG400_ORCH_X_MAX_MM`、`MG400_ORCH_Y_MIN_MM`、`MG400_ORCH_Y_MAX_MM`、`MG400_ORCH_Z_MIN_MM`、`MG400_ORCH_Z_MAX_MM`、`MG400_ORCH_R_MIN_DEG` 和 `MG400_ORCH_R_MAX_DEG`。它们没有默认值。每项必须是有限数，且最小值小于最大值。每个工位必须位于边界内，接近高度不得超过 Z 上限。

所有工位命令，以及下文的工位、托盘、吸取和坩埚步骤，都需要这些边界、`tool.toml` 和示教工位。缺少任一项时，命令或步骤被拒绝。

操作员先在实验室控制台的 Motion 工作区把机器人移至目标位置。示教时，控制台或其他控制器必须保持控制权。示教要求测量反馈新鲜、机器人空闲、没有锁定且没有未确认的停止。示教命令只读取服务描述和状态。它不会获取或释放控制租约、修改控制器工具配置或发送运动命令。

```sh
labctl station save tray-pick --approach 20 --zone tray
labctl station list
labctl station show tray-pick
labctl station rm tray-pick
```

`--approach` 是指尖 Z 坐标上方的垂直间隙，必须至少为 10 mm。命令示例使用 20 mm，操作员必须按测得的工作空间检查该值。`--zone` 默认为空名称。所有工位命令都可用 `--stations-file PATH` 覆盖工位路径。示教时，`--tool-file PATH` 覆盖工具路径。

文件为每个工位保存一个 `[stations.NAME]` 表。字段为 `x_mm`、`y_mm`、`z_mm`、`r_deg`、`approach_mm`、`zone` 和 `saved_at`。`saved_at` 是 Unix 时间戳。可选的 `via` 按行进顺序列出工位名称。

名称包含 1 至 64 个字母、数字、下划线或连字符。名称必须以字母或数字开头。引用的工位必须存在，不能重复或成环。重新保存工位时，会保留原路线。删除其他工位引用的工位会失败。

每次编辑都先检查完整工位图，再发布文件。并发编辑按顺序执行，文件以原子替换写入。记录库拒绝符号链接和特殊文件。

安装器创建 `/var/lib/mg400/robot`，属主为 `1000:1000`，模式为 `0750`。
父目录 `/var/lib/mg400` 的属主仍为 `root:1000`，模式仍为 `0750`。
旧路径 `/var/lib/mg400/tool.toml` 或 `/var/lib/mg400/stations.toml` 中的文件保持不变，安装器只打印手动移动提示。
按[机器人数据迁移说明](deploy.md#迁移到新主机)处理后，再通过新默认路径使用这些文件。
已有的 `MG400_ORCH_TOOL_FILE` 覆盖配置会保留。移动文件后，更新旧的覆盖配置。

写入或文件同步失败时，旧文件保持不变。替换后的目录同步失败会报错，但新文件可能已经可见。遇到该错误后，先检查工位文件，再重复编辑。

### 更换工具偏移

更换工具后，用 `retool` 写入新的实测偏移。已有工位时，不得手动编辑 `tool.toml`。

```sh
labctl station retool --offset DX DY DZ
```

把 `DX`、`DY` 和 `DZ` 替换为实测值，单位为毫米。命令按以下顺序执行：

1. 把 `stations.toml` 和 `tool.toml` 复制到同一目录下的 `NAME.bak-<UTC time>`。
2. 换算每个工位，使其法兰位姿不变。接近距离、区域、路线和 `saved_at` 不变。
3. 写入新的 `tool.toml`。

换算后的工位超出指尖工作空间时，命令停止，不修改任何文件。修改工作空间边界，或重新示教该工位。在没有配方运行时执行此命令。`--stations-file PATH` 和 `--tool-file PATH` 覆盖路径。命令输出新旧偏移、备份路径和换算后的工位。

## 工位转移

`robot.pick` 和 `robot.place` 使用工位名称。`robot.transfer` 把两者组合起来，公开参数为 `from` 和 `to`。这些名称与其他配方参数一样，接受完整的类型和未知字段检查。

```toml
[[steps]]
skill = "robot.transfer"
params = { from = "tray-pick", to = "tray-place", speed = 1 }
timeout_s = 60
on_fail = "hold"
```

片段中的数值只是示例，不是真机测量配置。

机器人必须已使能且空闲，反馈新鲜，并报告吸盘的实测输出。每次状态检查都确认本次运行持有控制权，且机器人实例未变。锁定、机器人错误、未确认停止或活动的键盘控制都会阻止转移。这些操作单元不会自动恢复控制权。

开始前，将机器人定位到示教工位或其接近位姿。实测法兰位姿必须与工具换算后的唯一工位匹配，各轴误差不超过 0.1 mm 或 0.1 度。起点未知或存在歧义时，操作单元拒绝运动。每段路线开始前，再次检查起始工位。

首次运动前，操作单元展开全部 `via` 路线，检查每个途经点和工具换算。换算后的法兰位姿必须为有限数。工位接近高度等于该工位 Z 加 `approach_mm`。

每段路线只在起始工位抬升至该工位的接近高度。随后按声明的 `via` 顺序，经过各途经工位的示教位姿。到达目标工位的接近位姿后，再下降至其示教位姿。每次移动均为直线。如果机器人已在目标工位，就跳过该工位的入站途经点。首个途经点若就是起始工位，也视为已到达并跳过。

拾取先下降，再发送 `vacuum suck`。拾取前吸盘必须关闭。吸气开启后，抬升至该工位的接近高度。放置要求吸气开启。它先下降，发送 `vacuum release`（短暂吹气后关闭），再抬升至该工位的接近高度。每次移动前后，状态检查确认吸气和吹气的实测输出：携带部件时吸气必须开启，否则必须关闭，吹气必须关闭。

安装真空开关并在 `src/mg400/suction.py` 中设置 `GRIP_DI`（默认为 `None`）后，机器人状态的 `vacuum.held` 报告是否吸住部件。吸气后 1 秒内未报告吸住时，操作单元发送 `vacuum release` 并失败。携带部件时 `held` 变为 `false` 表示掉落，运行暂停。放置后 1 秒内 `held` 未变为 `false` 时，操作单元失败。未设置 `GRIP_DI` 时，`held` 为 `null`，操作单元不能确认是否吸住部件。

`robot.pick`、`robot.place` 和 `robot.transfer` 接受整数参数 `speed`，默认值为 1。允许范围从 1 到机器人服务公布的速度上限，该上限固定为 20。参数或公布的上限无效时，步骤在运动前拒绝。所有移动通过 `execute` 发送，机器人服务仍执行速度和加速度限制。控制器保持 `User=0,Tool=0`。

每次运动都等待完成及下一份新鲜测量位姿。各轴测得的法兰坐标必须与请求途经点相符，误差不超过 0.1 mm 或 0.1 度。测量位姿暂缺时，只在步骤时限内继续读取。位姿不符、掉落、异常结果或超时都会暂停运行并请求停止，不重试运动或抓取。

首次抬升前，操作单元先进入起始工位的区域。前往后续具名工位区域前，也先进入对应区域。转移期间，源区域保持占用，直到测量确认已移向下一工位。独立抓取和放置只有在测量确认到达抬升端点后，才释放最后一个区域。失败时，保留持久占用记录，等待现场检查和有审计记录的恢复。

操作员必须确认每个端点接近位姿可达、能离开对应工作区域，且连接路线没有障碍。在 C 处，不得假定最小 10 mm 抬升可达。托盘上方的接近位姿必须使法兰 Z 低于摄像头 4 的 154 mm 限制。使用前，重新示教不合适的端点或路线。最小接近间隙不能证明物理间隙足够。软件途经点检查不验证碰撞或关节可达性。

## 吸盘取芯片

`recipes/chip-pick.toml` 要求字符串参数 `slot`。其步骤 `vision.pick_chip` 用吸盘吸取该托盘槽位中看到的芯片。步骤结束后，芯片保持吸住。在后续步骤中放置芯片，例如 `robot.place`。

- XY 取步骤观测到的已校准芯片中心。
- Z、R、接近距离、区域和路线取自 1 个名为 `tray` 的示教工位。示教时，把吸盘端点放在托盘内芯片的上表面。
- 该步骤不需要槽位工位，也不需要 `MG400_ORCH_CHIP_AXIS` 或 `MG400_ORCH_CHIP_R_*` 设置。它需要 `MG400_ORCH_TRAY_FILE` 和 `MG400_ORCH_TRAY_CAMERA`。

吸取前，步骤执行校准漂移检查和 1 次槽位观测。槽位必须恰好有 1 个芯片。证据缺失或含糊时，运行在运动前暂停。机器人必须从 1 个示教工位或其接近点出发，并位于已校准网格内。机械臂遮挡槽位，因此吸取后步骤不再检查该槽位。

```sh
uv run labctl run recipes/chip-pick.toml --param 'slot="groove_07"'
```

## 坩埚装载与卸载

`crucible.load` 把芯片从示教托盘工位转移到 `crucible-load`，再插入坩埚。
`crucible.unload` 退出坩埚，等待命名热区降温，再把芯片转移到示教托盘工位。
必须有名为 `crucible-load` 的示教工位，其区域为 `crucible-load`。托盘工位不得为 `crucible-load`。
路线上每个工位的区域都必须属于机器人。区域配置必须定义 `crucible-load`（属于机器人，要求 `stage_at_load`）和 `furnace-tube`（属于位移台，要求 `robot_clear`）。
不得给整个复合步骤声明 `zone = "crucible-load"`。机器人阶段释放该区域后，Insert 才能移动。

以有类型的配方参数提供这些值。默认值 `-1` 表示未设置，不表示安全限制。
参数未设置时，步骤读取对应的主机设置：`MG400_ORCH_CRUCIBLE_LOAD_MAX_C`、`MG400_ORCH_CRUCIBLE_UNLOAD_MAX_C`、`MG400_ORCH_CRUCIBLE_AWAKE_S` 或 `MG400_ORCH_CRUCIBLE_MAX_AGE_S`。
两者都缺失、非有限数或无效时，步骤在发送任何命令前拒绝。

| 参数 | 要求 |
| --- | --- |
| `load_max_c` | 非负数，装载时允许的高温炉 PV 上限 |
| `unload_max_c` | 非负数，卸载时允许的坩埚热区温度上限 |
| `awake_s` | 大于 0，不超过 60 秒 |
| `max_age_s` | 正数，测量数据的最大有效时长 |

实测工具偏移和示教路径遵循工位转移规则。
Insert 或机器人接收命令前，先检查两条完整路径和所有工具转换。
两种操作单元均接受 `speed`，默认值为 1，上限与工位转移相同，取服务公布的值。
机器人按示教路线高度移动，保留实测到位检查，以及 `contact`、`arrived` 和 `dropped` 检查。
操作单元不会自动归零、初始化、使能、解锁或重试设备。

电动台每轴必须有当前细分模式下的新鲜归零参考和软限位。
只读字段 `automation.at_poses` 将每个已配置位姿与实测位置比较：

```json
{"furnace":{"matched":false,"axes":{"bottom":true,"top":true,"insert":false}}}
```

运动、活动自动序列、反馈过期、参考不确定或停止不确定时，该字段为空。
只有全部轴匹配配置目标时，`matched` 才为真。它不假定命名位置等于 0。
装载要求 Bottom 和 Top 匹配高温炉目标，且 Insert 位于命名位置 `load`。
卸载要求完整实测位姿为 `furnace`。前提不成立时，不会发送该位姿命令来修复。
整个转移期间，Bottom 和 Top 必须保持空闲，且不离开已确认的对齐位置。

高温炉必须提供新鲜实测 PV、`STOP/COOLING`，且无运行序列、故障或持久化错误。
装载要求 PV 严格低于 `load_max_c`。机器人实测到达示教离开高度后，Insert 移动到命名位置 `furnace`。
Insert 留在管内时，运行保留 `furnace-tube` 的已知占用。装载成功不表示已离开该区域。

卸载先占用 `furnace-tube`，只移动 Insert 到 `load`，实测命名位置到位后才释放区域。
发送命令前，通过读取等待电动台现有冷却间隔结束。运动命令被拒绝后，不会重试。
随后请求明确的保持通电时长，并只读取命名热区 `crucible`。
读数最大值必须严格低于 `unload_max_c`。不得改用整帧温度。
操作单元固定采用 `api/describe` 提供的整数像素边界。每次读数必须匹配该矩形，且位于原生 160 乘 120 传感器内。
读数格式错误、过期、来自未来或非有限数时，拒绝转移。热成像服务的时限只能收紧 `max_age_s`。
热区仍热时，操作单元在步骤截止时间内继续读取。超时后暂停并请求停止。

每个保持通电阶段只发送 1 次明确请求。按毫秒截断后，该时长必须覆盖步骤剩余实际时间。
演练时间缩放不会延长该预算。租约续期不会延长通电时间。
等待后和每次动作前，重新检查服务所有权、测量新鲜度及服务提供的实例标识。
阻塞机器人命令执行期间，运行器也监视高温炉和热成像条件。检查失败时撤销步骤，并独立请求停止。
旧监视检查结束前，不得进入新阶段。

同一运行的后续卸载可以复用已知的管内占用。
独立卸载满足全部实测前提后，可以占用尚无声明的区域。
其他运行、未知或已终止运行保留的占用必须通过现有明确物理清空恢复。新运行不会自动接管。
软件检查不能证明物理间隙足够。操作者必须验证示教路径、电动台标定、温度限制和接近高度。

## 演练与安装后的命令

演练在数字环回地址创建并持有演示服务。它检查 `demo = true`，并在运行终止后关闭这些服务。它清除生产设备配置、代理配置和 Python 环境覆盖项。机器人演练要求仓库中有机器人服务 `apps/control_panel/`。演示工厂支持机器人、位移台、热像仪、高温炉和视觉，不支持显微镜。所需服务不受支持时，运行开始前就会报错。

演练只从环境中保留区域配置、工作空间、工位、工具、托盘、芯片、坩埚和漂移设置。转移演练保留明确提供的工位输入和区域配置路径。文档规定的配置路径默认值仍然适用。文件必须包含有效几何数据和命名区域定义。演练不会编造偏移、工作空间或区域配置。创建演示服务前，它先解析条件所需的服务。占用文件属于临时演练目录。

吸盘输出来自临时 SIM-01 模拟器。模拟器响应 `DOExecute`，并在反馈中报告 DO 位。

模拟器没有真空开关，因此 `held` 为 `null`。托盘演练场景在示教槽位吸气时取走芯片，在示教槽位放开时放下芯片。离线测试用带 `held` 的假机器人检查未吸住和掉落路径。演练不能证明物理间隙足够，也不能证明真机吸取成功。
设置 `MG400_ORCH_TRAY_FILE` 时，托盘演练只接受内置的合成托盘文档，拒绝真实托盘文件。

坩埚演练保留上述明确的安全输入。它从 `MG400_ORCH_CRUCIBLE_ROIS_FILE` 读取自有热成像演示的命名热区数据。
没有该数据时，不定义热区。它不会选择真实摄像头、生产高温炉或设备路径。
演示电动台启动时没有归零参考。离线测试明确让自有模拟器归零，并提供接触反馈。
高温炉演示持有自己的串口模拟器和临时状态。坩埚操作单元不发送加热或供气命令。

安装后，`labctl` 和 `mg400ctl` 使用同一分派器。配方命令必须精确匹配 `run`、`rehearse` 或 `runs`。工位命令必须精确匹配 `station save`、`station list`、`station show`、`station rm` 或 `station retool`。[智能体命令行](agent-cli.md)命令组为 `robot`、`stage`、`furnace`、`microscope`、`vision`、`thermal`、`camera` 和 `all`。管理命令仍要求 root。

root 调用配方或工位命令时，分派器先用 `runuser --pty` 切换至 UID/GID 1000，再启动 Python。智能体命令组使用不带 `--pty` 的 `runuser`，因此 stdout 只含 JSON 结果。它使用安装后的解释器绝对路径，并传入 `-I`。子进程接收主机配置文件中所有非空的 `MG400_*` 配置和固定的服务 URL。

root 演练不会读取主机配置文件。它从调用者环境接收 `MG400_*` 配置，不接收固定的服务 URL。

直接调用已安装命令时，实际和有效 UID/GID 都必须为 1000。它使用调用者的环境配置，不读取 root 配置文件。除演练外，它还接收固定的服务 URL，调用者的 `MG400_*` 值优先。本地 `uv run labctl` 使用开发者身份。用 `--runs-dir` 指定本地可写目录。
