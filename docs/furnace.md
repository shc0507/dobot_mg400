# 炉温与气体控制

炉控网页通过同一服务供操作员和自动化客户端控制炉温、气体流量及有终点的序列。
摄像头和录像控件暂不可用。另见[主机部署](deploy.md)和[炉控生命周期决策](adr/0005-furnace-lifecycle.md)。

## 真机使用前

完成监督下的硬件验证并取得操作员批准前，不得启动真实加热。
请与操作员核对串口设备、气体名称、满量程流量、温度上限和工艺限制。
软件不能代替独立过温保护、气体物理隔离或紧急切断装置。
监督下的硬件操作前，先使用演示模式。不得让其他程序同时连接同一炉控器或气体控制器。
验证新序列时，使用保守的低温。保持物理急停装置随手可用。

## 演示模式

在仓库目录运行：

```sh
uv run python -m furnace --demo --bind 127.0.0.1 --port 8769
```

打开 `http://127.0.0.1:8769/`。网页显示演示标记。
演示模式使用模拟串口和独立的临时状态目录。
它忽略生产串口路径和气体配置，不模拟工艺安全或真实炉温精度。
访问密钥和监听地址规则仍然适用。关闭进程时，模拟输出停止，临时状态删除。

## 配置

主机服务读取 `/etc/mg400/mg400.env`。只有 `MG400_OPTIONAL_SERVICES` 包含 `furnace` 时，安装器才安装它。
安装器将 `furnace` 依赖组装入 `.venv`，只授予服务附加组 `dialout`。
安装器创建 `/var/lib/mg400/furnace`，属主为 `1000:1000`，权限为 `0750`。

| 配置项 | 默认值 | 规则 |
| --- | --- | --- |
| `MG400_FURNACE_BIND` | `127.0.0.1` | 监听地址 |
| `MG400_FURNACE_PORT` | `8769` | 端口范围为 `1` 至 `65535` |
| `MG400_FURNACE_BASE_PATH` | `/` | 网页和 API 前缀，例如 `/heat/` |
| `MG400_FURNACE_TOKEN` | 安装器生成 | 至少 `24` 个可打印 ASCII 字符 |
| `MG400_FURNACE_SERIAL` | 空 | `/dev/serial/by-id/` 下的炉控串口，启动前必须填写 |
| `MG400_MFC_SERIAL` | 空 | `/dev/serial/by-id/` 下的独立气控串口，访问气体控制器前必须填写 |
| `MG400_FURNACE_SLAVE` | `1` | 整数地址，范围为 `1` 至 `247` |
| `MG400_FURNACE_MAX_C` | `1000` | 有限上限，大于 `0`，不超过 `1000` °C |
| `MG400_FURNACE_MAX_RAMP` | `100` | 有限上限，大于 `0`，不超过 `100` °C/min |
| `MG400_FURNACE_GAS_MAP` | 空 | 操作员提供的通道到气体名称的 JSON 映射 |
| `MG400_FURNACE_IDLE_GAS` | 全关 | 失去客户端超时、冷却完成或恢复状态不明时使用的通道到百分比 JSON 映射 |
| `MG400_FURNACE_ORPHAN_GRACE_MIN` | `15` | 至少为 `0` 的有限宽限时间，单位为分钟 |

气体映射使用通道键 `0`、`1`、`2`，分别对应 MFC 地址 `7`、`8`、`9`。
百分比表示对应控制器满量程流量的占比，不表示通用的体积流量。
操作员提供气体映射前，服务拒绝气体命令。停止功能仍然可用。
空闲气体计划默认为全关。任何非零空闲计划均须由操作员决定工艺要求。

配置文件中的气体映射和空闲气体 JSON 对象必须用单引号包围。
安装器原样保留内部双引号，拒绝转义、撇号、控制字符、重复键和非有限数字。
其他配置项仍遵循原有的引号和反斜杠限制。
以下空对象只展示语法，不指定气体，也不授权输出：

```ini
MG400_FURNACE_GAS_MAP='{}'
MG400_FURNACE_IDLE_GAS='{}'
```

保持配置文件私密。不得把访问密钥放入 URL 或共享截图。
通过 VPN 访问时，使用 [Olares 网络配置](olares.md#网络)中的监听地址和 TCP 规则。
监听非回环地址时必须配置有效密钥。未配置密钥时，只接受无转发标头的回环主机请求。

## 打开网页并取得控制权

1. 打开配置的网页地址。
2. 在访问字段输入服务密钥，点击 **Use token**。
3. 点击 **Take control**，或在无人持有控制权时发送明确的手动命令。
4. 设置输出前，查看连接和故障状态。

网页只在内存中保存密钥，并通过 bearer 标头发送。
重新加载网页会清除密钥。会话存储只保存网页的客户端标识。
手动控制每 `1` s 续期，租约有效期为 `3` s。
续期失败时，排除原因后必须明确点击 **Take control**。
自动化客户端持有租约时，手动命令被拒绝，复用其客户端标识的请求也不例外。
停止按钮仍然可用。**Release control** 释放租约，不立即停止有终点的序列。

服务启动时尝试只读连接炉控器，并执行下文的恢复规则。
设备断开时，修复连接后明确点击 **Connect**。
服务不自动重连。气体连接须由独立的明确命令或明确的气体操作触发。

## 炉温与状态

PV 是实测温度。SV 是当前目标温度。炉控器停止时，不显示活动 SV。
API 单独保留存储的目标温度，供诊断使用。
网页显示 RUN、HOLD、STOP 和连接状态，约每 `1` s 更新。
HOLD 暂停控制器程序，但继续调温。STOP 关闭加热，炉体被动冷却。

输入目标温度和斜率后，点击 **Apply and run**。
目标温度必须至少为 `0` °C，且不超过配置上限。斜率必须为正，且不超过配置上限。
驱动在 RUN 前把目标温度同时写入 `SP1` 和 `SP2`，用当前 PV 计算爬升时间。
控制器进入步骤 `2` 时，服务请求并验证 HOLD。
不得仅凭温度达到目标就认定已进入 HOLD。

## 序列与气体

1. 在序列表中添加或删除行。
2. 填写每行的目标温度、斜率和保温分钟数。
3. 按需填写各步骤的气体百分比。气体字段为空时，对应通道保持原值。
4. 任一步骤设置气体时，必须填写结束气体百分比及其停止温度阈值。
5. 点击 **Start sequence**。它直接使用当前表格，无须先保存。

只有确认 HOLD 且 PV 与目标温度相差不超过 `1` °C 时，保温计时才开始。
保温时间结束后，服务进入下一步。爬升和稳定时间使总时长大于各步保温时长之和。
保温期间，服务不重复发送温度设置命令。
最后一次保温结束后，加热停止。结束气体计划持续到 PV 低于阈值。随后服务应用空闲气体计划，默认为全关。

运行中点击 **Save / update sequence** 可应用编辑。
当前步骤按数字索引选择。在它之前插入或删除行，会改变该索引对应的行。
表格缩短后若当前索引不再存在，服务选择新的最后一步。
仅编辑字段不会改变输出。保存或启动序列时才发送编辑内容。
状态轮询保留编辑器内容。网页突出显示当前行，并显示剩余保温时间。
修改当前目标温度、斜率或气体计划时，服务重新应用该步骤并重置保温计时。
只修改当前保温时间或后续步骤时，当前输出配置保持不变。
服务持久保存已接受的编辑，包括后续气体计划。

气体面板分别显示请求百分比、实测百分比和阀门回读。
**Send flow** 应用填写的百分比。**100%** 明确请求满量程流量。
缺少可选回复表示未验证，不证明流量为零或阀门已关。
通信失败或回复无效会锁定控制。**Close valve** 和 **Stop all gas flow** 仍然可用。
请核对实际流量，并按要求使用独立隔离装置。

## 客户端丢失、恢复与关闭

| 情况 | 行为 |
| --- | --- |
| 序列失去客户端 | 继续有终点的步骤和结束气体冷却计划 |
| 无终点的设定值失去客户端 | 开始配置的宽限计时，超时后停止加热并应用空闲气体计划 |
| 无客户端持有控制权 | 停止可用，其他命令必须先取得控制权 |
| 启动时读到与状态记录匹配的 RUN 或 HOLD | 仅当目标温差不超过 `2` °C 且实时配置满足上限时，恢复有效的已存意图 |
| 启动时读到不匹配的 RUN 或 HOLD | 尝试停止加热并应用空闲气体计划，然后锁定，等待确认 |
| 启动时读到 STOP | 保持空闲，即使已存状态包含冷却计划 |
| 收到 SIGINT、SIGTERM 或 SIGHUP | 分别尝试停止加热和气体，关闭通信连接后退出 |

服务在阶段变化时及保温期间每 `60` s 原子写入 `state.json`。
重启后保留按时钟时间记录的保温和客户端丢失时间。
状态文件及持久的 `.state.json.lock` 权限为 `0600`。
不得通过删除状态文件或锁文件清除故障。
命令中断或结果不明时，必须检查并确认。
只有检查设备并验证 STOP 后，才能点击 **Acknowledge fault**。
存储失败会锁定运行中的控制，服务仍分别尝试停止各类输出。
若所有持久写入和失效处理均失败，服务不能保证故障记录持久保存。

**Stop heat and gas** 和 **Stop sequence** 取消剩余步骤，并尝试停止两类输出。
只有验证加热和气体均已停止，响应才确认停止。否则响应保持未确认。
停止不受租约归属或到期回调失败的限制。身份验证和请求格式检查仍然适用。

主机维护前，必须与所有客户端协调关闭操作。
`mg400ctl stop furnace` 和 `mg400ctl restart furnace` 拒绝中断活动序列或冷却气体计划。
实时状态不可用、格式错误、断开或锁定时也拒绝操作。`all` 和混合目标列表在修改任何服务前执行同样的检查。
仅在协调好中断后使用 `--force`。该选项允许关闭服务，并请求停止加热和气体。必须核对停止结果。
状态检查仅作提示性保护：其他客户端可能在检查之后、systemd 操作之前启动序列。
另见[部署日常命令](deploy.md#日常命令)。

## API 与故障排查

服务提供[仪器契约](adr/0001-instrument-service-contract.md)及原有炉控网页路由。
两类路由共用生命周期、上限和气体策略。配置密钥后，所有 API 读取均须携带密钥。
修改请求必须使用 JSON 和 `X-MG400-Client`。网页和 API 路由均检查 Host、Origin 和转发标头。
通过 `GET /api/describe` 读取命令格式，通过 `GET /api/state` 读取状态。
所有路径均使用配置的基础前缀。

连接失败时，检查配置的稳定设备路径和访问权限。
炉控器使用 `9600` 波特率、`8` 个数据位、无校验和 `1` 个停止位。必须与配置的从站地址一致。
控制被拒绝时，先检查租约持有者、气体映射、上限及故障，再明确重试。
停止未确认时，检查设备并使用物理保护。不得把 HTTP 成功响应当作物理停止确认。
使用 `mg400ctl logs furnace` 读取服务事件。
