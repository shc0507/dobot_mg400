# 位移台

[返回项目主页](../README.md)

`stage-panel` 服务通过 USB 串口控制 3 个 Arduino 电机，波特率为 115200。Arduino 执行编码器闭环控制。控制台按电机轴圈数发送目标并读取实测位置。请使用 Lab Console 的 **Motion** 工作区。位移台服务没有独立网页。

使用 [Stage Controller v3](../firmware/stage-controller-v3/README.md)。它通过 TCA9548A 多路复用器连接 AS5600 编码器，并读取上下限开关。旧脉冲固件仍能连接和停止，但不能使用编码器移动控件。

| 电机 | 控制台轴 | 正方向 | 负方向 |
| --- | --- | --- | --- |
| `bottom` | Bottom (Y) | 上，`ccw` | 下，`cw` |
| `top` | Top (X) | 右，`ccw` | 左，`cw` |
| `insert` | Insert | 进，`ccw` | 出，`cw` |

## 连接

访问 [Olares](http://100.64.0.1:8080/) 时，保持 LarePass VPN 连接。打开 **Motion**，获取位移台控制权，选择 Arduino 串口，再选 **Connect**。串口列表随服务状态自动更新。

服务启动时不打开串口。打开串口可能重置 Uno。连接过程等待约 2 s，再读取状态和能力。只有 1 个进程能占用串口。连接前关闭 Arduino 串口监视器。服务不会自动重连或重试移动。

上传固件前，停止运动并运行 `labctl stop stage`。按固件指南上传。重新接回 Arduino 后，检查 `/dev/serial/by-id/`，启动服务，再从控制台连接。

在连接 Arduino 的电脑上运行：

```sh
uv sync
uv run stage-panel
```

等效模块命令为 `uv run python -m stage_controller`。Linux 服务用户必须能读写串口，通常通过 `dialout` 组授权。控制台使用 `http://127.0.0.1:8767/`。

无硬件时，运行 `uv run stage-panel --demo` 并连接 `DEMO`。本地控制台预览方法见[仪表盘](dashboard.md#离线运行)。演示模式不打开串口硬件，不能验证实际精度或机械间隙。

## 控件

连接或移动前，先获取位移台控制权。只有 1 个控制者能持有租约。默认租约为 3 s，过期会请求停止。释放租约不会停止定量移动。释放前，先停止或等待移动完成。

- 位置使用圈数，速度使用圈/秒。固件固定采用 1/8 细分。默认整步数为每圈 200，默认速度为 0.25 圈/秒。使用电机报告的速度上限，在这些默认值下通常为 0.5 圈/秒。
- 按住方向按钮即可移动，松开即停。**Keys** 使用 I/K 控制底部上/下，J/L 控制顶部右/左，U/O 控制插入进/出。
- 每个轴的移动控件旁都有 **Clear fault**。它要求位移台控制权，不移动电机。X/Y 图的各角显示最小和最大圈数限位，未知限位显示 **—**。
- **Moves, limits and calibration** 包含相对移动、绝对目标和设置控件。相对移动接受 0.001–10000 圈。它要求编码器反馈正常且未过期，但不要求完成标定。
- **Move to target** 使用绝对坐标。它要求完成标定、有效限位和未过期的反馈。每次只有 1 个位移台轴移动。
- **Stop stage**、各轴的 **Stop** 和 **STOP ALL MOTION** 不要求控制权。停止会取消标定和定量移动。
- 反馈显示编码器状态、实测速度、帧龄、开关状态和故障。过期或不可信的位置显示 **—**。页面更新时保留输入的速度和目标。

浏览器每 150 ms 刷新按住状态，控制台每 0.2 s 续期。0.5 s 内无浏览器刷新时，控制台松开按住。固件在最后一次保活后 1 s 停止按住移动。失去焦点、隐藏页面或离开 Motion 时，页面松开按住。

移动完成后，不执行主动位置保持。驱动器空闲 10 s 后休眠。编码器通电时仍测量手动转动。断电期间转过的整圈数无法由 AS5600 恢复。

## 位移台校准

对每个轴分别使用 **Auto calibrate**：

1. 电机沿 `cw` 寻找下限开关。
2. 下限坐标设为 0，再沿 `ccw` 寻找上限开关。
3. 记录上限坐标，移到中点。
4. 标定完成且反馈稳定后，可使用绝对目标。

标定阶段为 `none`、`lower`、`upper`、`center`、`done`、`cancelled` 和 `failed`。活动阶段不能启动新移动。只有收到请求才开始标定。

**Reset position** 将实测位置设为 0，并清除全部限位。**Set limit here** 将正坐标设为上限，负坐标设为下限，拒绝 0。**Clear upper** 和 **Clear lower** 只清除所选限位。每次更改都会使已完成的标定失效。

正常触发开关时，电机停止朝该开关移动，仍可向反方向移动，坐标不归零。已设软限位也限制行程。方向暂停和警告计数不会启动标定。**Clear fault** 清除反馈故障，不移动电机。已存限位且位置跟踪失效时，先清除全部限位，再恢复故障。

位置、限位和标定状态保存在 Arduino RAM 中。重置或断电会使其失效。使用已存绝对目标前，重新标定。Sample Transfer 将命名坐标保存在磁盘，但已存配置不会恢复 Arduino 参考。

旧 `steps_per_mm`、毫米几何、命名脉冲位姿和相机参考均未启用。服务不使用它们生成编码器目标。缺少旧文件不会阻止编码器控制。

旧编排技能 `crucible.load`、`crucible.unload` 以及区域检查 `stage_at_load` 仍需迁移到编码器坐标。它们会在运动前拒绝新位移台状态。使用 Sample Transfer 执行基于圈数的流程。

## 服务配置

systemd 单元为 `mg400-stage-panel.service`，`labctl` 名称为 `stage`。服务以用户/组 `1000` 运行，并加入 `dialout` 组。默认监听 `127.0.0.1:8767`，正式路由位于 `/api/` 下。`/contract/api/` 别名使用同一组处理器和租约。

### 配置项

| 环境变量 | 参数 | 默认值 | 用途 |
| --- | --- | --- | --- |
| `MG400_STAGE_SERIAL` | `--serial` | 未设置 | 只提供此 Arduino 串口 |
| `MG400_STAGE_CONFIG` | `--config` | `/var/lib/mg400/stage/stage.toml` | 兼容保留的旧几何文件，不用于编码器移动 |

参数 `--bind`、`--port` 和 `--base-path` 可覆盖本地监听默认值。Olares 客户端使用固定的位移台端点。

参数覆盖环境变量，空环境变量视为未设置。Olares 读取 `/etc/mg400/mg400.env`。建议 Arduino 使用稳定的 `/dev/serial/by-id/` 路径。已设串口不存在时，列表为空。演示模式忽略已设串口路径。

### 启动与停止

```sh
ls -lL /dev/serial/by-id/
labctl start stage
labctl status
labctl logs stage
labctl stop stage
```

修改配置或安装更新代码后，运行 `labctl restart stage`，再从控制台连接。该单元不随系统启动。异常退出后，服务在 3 s 后重启。退出状态 2 表示启动配置错误，此时不重启。

## 接口

命令格式、状态字段、租约和完成规则见[位移台自动化契约](development.md#位移台自动化契约)。通过控制台转发或持有租约的契约客户端修改状态。停止使用专用契约停止路由，不要求租约。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 无串口 | 检查 USB 供电、数据线和 `/dev/serial/by-id/`。核对 `MG400_STAGE_SERIAL`，等待串口列表更新。 |
| 权限不足 | 检查 `dialout` 权限。本地组成员变化后，重新登录。 |
| 串口被占用 | 关闭占用同一 Arduino 的其他位移台服务和串口监视器。 |
| 已连接但不能移动 | 检查编码器固件能力、固定 1/8 模式、帧龄、编码器状态、开关和冷却时间。 |
| 编码器离线或磁铁故障 | 检查编码器供电、多路复用器通道、I²C 接线和磁铁位置。修复后使用 **Clear fault**。 |
| 绝对目标不可用 | 完成 **Auto calibrate**，检查全部限位，等待未过期的空闲反馈。 |
| 方向警告 | 检查联轴器、编码器方向和机械阻力。出现重新标定建议时，按提示操作。 |
| 停止未确认或连接断开 | 确认实际状态，重启位移台服务并重新连接。后续空闲反馈不会单独清除服务的停止故障。 |

软件停止要求控制链路可用。USB 断开或主机故障可能阻止停止确认。固件中的定量移动可能继续到目标或固件限位。服务不会重试移动。
